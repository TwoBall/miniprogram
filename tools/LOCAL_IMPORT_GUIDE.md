# 本地修改JSON文件后导入 - 操作指南

## 方案说明

既然您已经导出了数据库JSON文件，我们可以：
1. 在本地批量修改JSON文件中的字段名
2. 在云开发控制台清空对应集合
3. 导入修改后的JSON文件

这个方案比云函数迁移**更简单直接**！

## 操作步骤

### 步骤1: 准备数据文件

1. 在 `tools` 目录下创建 `data` 文件夹（如果还没有的话）
2. 将您之前导出的JSON文件放入 `tools/data` 文件夹，例如：
   ```
   tools/
   └── data/
       ├── students.json
       ├── users.json
       ├── attendance_records.json
       └── feedbacks.json
   ```

### 步骤2: 运行重命名脚本

在命令行中执行：

```bash
cd tools
node rename-fields.js
```

脚本会：
- ✅ 自动识别每个集合类型
- ✅ 将 `students.name` → `students.studentName`
- ✅ 将 `users.name` → `users.userName`
- ✅ 将 `attendance_records` 中的嵌套记录也一并修改
- ✅ 保持其他字段（如 `_id`, `_openid`, 日期等）不变
- ✅ 输出修改后的文件到 `tools/data/modified/` 目录

### 步骤3: 检查修改结果

1. 打开 `tools/data/modified/` 目录
2. 随机检查几个文件，确认：
   - ✅ `name` 字段已改为 `studentName` 或 `userName`
   - ✅ 其他字段保持不变
   - ✅ `_id` 字段保留（重要！）
   - ✅ JSON格式正确

### 步骤4: 备份现有数据

**重要：在删除数据前，请确保已备份！**

- 保留原始导出的JSON文件作为备份
- 或者再次从云开发控制台导出一次

### 步骤5: 在云开发控制台导入数据

对于每个需要修改的集合（`students` 和 `users`）：

#### 5.1 清空集合数据

**方式A: 删除并重建集合（推荐）**
1. 在云开发控制台 → 数据库
2. 找到 `students` 集合
3. 点击"设置" → "删除集合"
4. 重新创建 `students` 集合
5. 对 `users` 集合重复以上步骤

**方式B: 手动删除所有数据**
1. 在云开发控制台 → 数据库
2. 打开 `students` 集合
3. 点击"删除" → "批量删除"
4. 选择所有记录并删除

#### 5.2 导入修改后的数据

1. 打开对应的集合（如 `students`）
2. 点击"导入"按钮
3. 选择 `tools/data/modified/students.json` 文件
4. 选择导入模式：
   - ✅ 选择 **"插入新记录"**
   - ⚠️ 不要选择"更新现有记录"（因为已清空）
5. 点击"确定"开始导入
6. 等待导入完成

#### 5.3 验证导入结果

1. 检查记录数是否正确
2. 随机打开几条记录，确认：
   - ✅ `studentName` 或 `userName` 字段存在
   - ✅ 旧的 `name` 字段不存在
   - ✅ 其他字段正常

### 步骤6: 重新部署更新后的云函数

因为代码已经更新为使用新字段名，需要重新部署云函数：

1. 右键点击 `cloudfunctions/students` → "上传并部署：云端安装依赖"
2. 右键点击 `cloudfunctions/user` → "上传并部署：云端安装依赖"
3. 右键点击 `cloudfunctions/attendance` → "上传并部署：云端安装依赖"
4. 右键点击 `cloudfunctions/export` → "上传并部署：云端安装依赖"
5. 右键点击 `cloudfunctions/transfer` → "上传并部署：云端安装依赖"

## 注意事项

### ⚠️ 重要提醒

1. **一定要备份数据**：在删除集合前，确保有完整备份
2. **保留 `_id` 字段**：导入时必须保留原有的 `_id`，否则关联关系会丢失
3. **日期字段处理**：
   - JSON导出的日期是字符串格式 `$date`
   - 导入时微信云开发会自动转换
   - 如果日期显示异常，可能需要手动处理

4. **操作顺序**：
   - ✅ 先修改代码 → 再修改数据库
   - ❌ 不要先修改数据库 → 再修改代码（会导致功能异常）

### 💡 优势

相比云函数迁移方案：
- ✅ 更直观 - 可以直接看到数据变化
- ✅ 更可控 - 可以在导入前检查修改结果
- ✅ 更简单 - 无需部署额外的云函数
- ✅ 更彻底 - 直接替换，没有残留旧字段

### 🔍 如果遇到问题

**Q: 导入后字段还是旧的？**
A: 检查是否使用了 `tools/data/modified/` 目录下的文件，而不是原始文件

**Q: 导入后 `_id` 变了？**
A: 确保JSON文件中保留了 `_id` 字段，且导入时选择了正确的模式

**Q: 日期字段显示异常？**
A: 检查JSON中的日期格式，应该是 `{"$date": "2025-12-25T00:00:00.000Z"}` 格式

**Q: 部分数据丢失？**
A: 检查JSON文件大小和记录数，确保导入完整

## 与云函数迁移方案的对比

| 特性 | 本地修改+导入 | 云函数迁移 |
|------|--------------|-----------|
| 操作复杂度 | ⭐⭐ 简单 | ⭐⭐⭐⭐ 较复杂 |
| 数据安全性 | ⭐⭐⭐⭐⭐ 可完全控制 | ⭐⭐⭐⭐ 有回滚 |
| 停机时间 | 需要短暂停机 | 无需停机 |
| 旧字段残留 | 无 | 有（需手动清理）|
| 适用场景 | 数据量中小型 | 数据量超大型 |

**推荐**: 对于您的场景，**本地修改+导入**更合适！
