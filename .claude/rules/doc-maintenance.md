# 文档维护规则

当你修改或创建代码文件时，**必须**执行以下步骤：

## 0. 先读取现有文档（重要！）

修改文件前，**必须先检查并读取**：
- 所属文件夹是否已有 README.md？**如果有，先读取它**
- 文件是否已有头部注释？**如果有,保留并更新**

⚠️ **禁止直接覆盖创建**！

## 1. 文件头部注释

每个 JavaScript 代码文件必须有标准三行注释：

```javascript
// input: {输入描述}
// output: {输出描述}
// pos: {架构位置描述}
```

**示例：**

```javascript
// input: 用户输入的登录信息（用户名、密码）
// output: 返回用户登录状态和用户信息
// pos: 页面层 > 登录模块 > 登录逻辑
```

## 2. 文件夹 README.md

修改文件后，更新所属文件夹的 README.md：
- 如果已存在：先读取，增量更新文件索引
- 如果不存在：创建新文件

README.md 格式要求：

```markdown
# {目录名}

<!-- 一旦我所属的文件夹有所变化，请更新我 -->

## 架构说明

{3行以内的描述}

## 文件索引

- `file1.js` - 功能描述
- `subfolder/` - 子目录描述
```

## 3. 上级目录传播

检查上级目录的 README.md 是否需要更新：
- 如果新增了子目录，在上级 README 中添加索引
- 如果修改了模块的核心功能，更新上级 README 的描述

## 4. 文档维护报告

完成代码修改和文档更新后，输出简要报告：

```markdown
## 文档维护报告

### 修改的文件
- path/to/file.js

### 更新的文档
- path/to/README.md
- parent/README.md (如果需要)

### 文档变更说明
- 简要说明文档更新的内容
```

## 5. 特殊文件类型

### 小程序页面文件
对于 `.wxml`、`.wxss`、`.json` 等小程序页面配置文件，在对应的 `.js` 文件中维护注释即可，无需单独添加。

### 云函数
云函数目录的 `index.js` 必须包含：
```javascript
// input: 云函数调用参数描述
// output: 云函数返回值描述
// pos: 云函数层 > {功能模块名}
```

### 组件
组件的主 `.js` 文件必须包含标准三行注释，说明组件的输入（properties）和输出（events）。

## 注意事项

- 使用**中文**编写所有文档和注释
- 保持文档简洁，避免过度详细
- 优先更新现有文档，不要创建重复文档
- 文件索引按字母顺序或逻辑顺序排列
